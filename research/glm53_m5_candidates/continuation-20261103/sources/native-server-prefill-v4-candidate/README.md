# Source candidate: one-request HTTP prefill with CPU v4 geometry

This package is **source only**. No compiler, native binary, server, model, GPU, test or AST check has run for it. The CPU v4 full-model run in another task is active and has no inherited positive verdict. A/B/C, shared cache and performance are unqualified. Original V4/noBLAS/CPU helper sources and measured libraries are unchanged.

The delta applies after the separate frozen `native-server-noblas-candidate/server-cpu-no-blas.patch`, on the exact reconstructed V4 tree. The unchanged noBLAS header is included here as a dependency; the new delta changes only standalone server startup, server prompt assembly/validation/traces and an opt-in policy header. No `llama_context_params` or ggml/llama ABI is extended, no math library or core splitter is changed.

`AIRLLM_GLM53_PREFILL_V4` is immutable per process and OFF by default; values other than0/1 refuse. Enabling it requires the actual applied standalone `AIRLLM_GLM53_CPU_NO_BLAS=1` policy, pinned original GLM architecture/geometry checks and actual registry checks. It also requires CPU10/GPU0, `device none`, no op/KV offload, mmap/no-repack, context2048, logical batch32 and ubatch32, one slot/sequence, no warmup, no context shift, no speculative/MTP/LoRA/vision/embedding/NUMA/unified cache, F16 cache, `swa_full=true` matching the observed native helper, and default flash/RoPE/YaRN. All five baseline native environment knobs must equal1, including `AIRLLM_DENSE_PREFETCH_MAX_COLS=1`. The launcher must still enforce exact native package/model receipts, UID ownership, AC/awake, PID identity, RSS8.5GiB, swap32MiB and the original budgets. This source is not a replacement launcher.

The admitted API is one native `/completion` string prompt per HTTP request, one completion, slot0, `cache_prompt=false`, no cache reuse, no shared/child tasks or adapters, native text IDs, full prompt1..1800 and prompt+output<=2048. The exact effective default sampler chain with temperature0/seed42, neutral/default DRY/XTC/dynatemp/mirostat/adaptive/penalty modifiers, natural EOS enabled, output budget1..512 and the original unmodified RONIN payload are required. CLI, prompt arrays/token arrays, other inference formats, embeddings/decisions/speculation and state restore/save/control mutations refuse. Idle slot erase and read-only status/metrics remain possible; active erasure refuses. The rejection is explicit before slot launch, and an incompatible effective assembly/view aborts its request and invalidates its context.

Within that single request, the prompt assembler determines `take` from the real next native position and complete prompt end. It stops at absolute fences128/208/256/384/512; rounds windows>16 down to a multiple16 when necessary; then preserves CPU8 odd tails9/11/13/15 as8+1/3/5/7. Thus helper32 boundaries192→208→240→256 are retained instead of a logical seam224. At542 the tail is16+14; at521 it is8+1. The copied pure rule identifies the CPU helper source SHA `c37423f3444ec5f986515e3e2c31abba32a2d43967eb0e49bde4290335bc3a78`, but this does not establish server fidelity.

The native `batch.add`/render path retains all original tokens, positions and output masks. Only the last token of the complete prompt is marked for logits and sampling; intermediate capped calls do not sample and do not create additional HTTP requests. The existing successful decode1 generation path retains its token/output behavior. Prefill calls additionally synchronize before the completion trace, matching the diagnostic helper's explicit synchronization. Every actual rendered call is independently checked against its expected take, sole sequence, contiguous positions and exact output flags. Trace events `AIRLLM_GLM53_PREFILL_V4` record before/after, task ID, slot, offset, token count, original prompt end, phase, logical/physical maxima and logits flags. A before event has no returncode; only an after event records the observed returncode. No raw prompt/token text is logged by this delta.

Any nonzero decode result, including abort/KV warning, fails the experimental request without reducing the batch/retrying under a different geometry. Error cleanup clears the slot prompt/memory. Pre-assembly exceptions use the existing `pre_decode` catch, which clears the experimental slot before a future request. Generic OFF behavior keeps its original code path. This requires future executable refusal and cleanup tests; it has not been exercised.

Conditional `/props` data exposes policy, helper source identity, hardcoded boundaries/limitations and a mutex-protected observation made after actual context creation. Public getters confirm n_ctx/n_batch/n_ubatch/n_seq_max/n_rs_seq; configured fields are labelled configured, not resolved defaults. All qualification fields remain false. Trace is currently at logical-call level: actual hybrid-memory ubatches and numeric callback data remain uninstrumented.

## Remaining differences and required proof

Compared with the helper, server initialization uses `common_init_from_params`, server sampler/queue/slot lifecycle, server output limits and per-sequence prompt clearing. In particular the normal server sets `n_outputs_max=1` and `n_outputs_max_per_seq=1`; the helper describes native defaults0/1 before resolution. The server requires explicit `--no-kv-offload` here because its common default otherwise differs from the helper's `offload_kqv=false`. Request sampler conditioning is also a separate contract. Equal batch sizes and boundaries do not remove these differences. The actual build/runtime/source hashes and all effective flags need a new identity; do not substitute a CPU-helper cache key.

Before any HTTP numerical qualification, add separate bounded research instrumentation for all118 named routes/router/KDA series with actual axes/strides/raw SHA, complete154880 F32 final logits, actual ubatch boundaries, ordered state-write observations, complete checkpoints/final state and four continuations including IDs/logits/poststate, plus replay and own guard/key validation. `n_probs` and the current metadata traces cannot provide those proofs. Existing full comparators continue to reject this unmeasured server; a new strict cross-runtime comparator is required. The current profile has no common-cache restore support.

After numerical proof, C is still a separate real1→600→1 campaign with600 identities, one engine/slot, exact host history and useful natural EOS under Max512/2700s logical/7200s global budgets. An EOS diagnostic or an early window cannot qualify C. No C gate is bypassed by this source.

## Source revision2, still unexecuted

The independent source review of revision1 found three concrete defects: descriptor fields used common-parameter names on a native context-parameter struct; `swa_full` rejected the true value observed in the helper; and temperature0/seed42 alone did not guarantee the effective sampler included a temperature stage. Revision2 corrects the fields to `cp.type_k/type_v`, requires `--swa-full`, and pins the actual parsed default chain and neutral/default modifiers. In particular `samplers:[]`, changed chains and nonneutral DRY/XTC/dynatemp/mirostat/adaptive settings refuse. The RONIN request is never rewritten. A request-admitted trace records the effective chain/greedy settings. The old patch/manifest/README are retained under `revisions/source-v1` as unexecuted history, not measured proof. No test/AST/compiler/native call has validated revision2 yet.

The sampler gate also refuses reasoning-budget/control overrides, preserving unbounded native Max conditioning. The model-derived `logit_bias_eog` table is populated by common initialization even when inactive, so it is not required to be empty; `ignore_eos=false` and no active request `logit_bias` remain mandatory. The ordinary server sampler can still apply the pinned model's native suppression rules, unlike the helper's direct argmax; this is another reason to require new continuation parity rather than assert it from temperature0.
